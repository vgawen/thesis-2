### 1.1 “真实目标移除对照实验”到底移除什么

这里的“目标”不是测试用例本身，也不是旧定位器，而是 ReproBreak 标注的 `new_locator` 所指向的元素，即 UI 变更后测试本应操作的正确元素（ground truth）。

具体做法：

1. L1 抽取器把页面上的可交互元素抽成候选集（LocatorSheet 记录）。
2. 解析器把 `new_locator` 映射到其中一条记录，这条记录就是真实目标。
3. 实验时把这条记录从候选集中移除，再让修复器在剩余候选里选择。
4. 此时没有正确答案，正确行为是输出 `CANDIDATE_IDX: -1`（弃权）。修复器只要给出一个能解析的选择器，就必然指向错误元素，记为一次隐性误修复。

注意：移除的是候选列表里的正确记录，不是页面 DOM 节点，也不是旧定位器，更不是整个测试用例。

**定名结果：真实目标移除对照实验**（2026-10-21 确认）。这个名字明确了两点：移除的是真实目标（ground truth），不是任意候选；实验采用对照条件，观察目标缺失时修复器是否弃权。

首次出现用全称，之后可简称“真实目标移除实验”。标题、摘要、表题第一次出现时用全称。

## 4. 术语约定段（建议插入 1 节末或 2 节开头）

> 本文把 Playwright 中按选择器查找元素的 API 对象称为定位器（locator），把修复器输出的定位表达式称为选择器。文中把 data-testid、aria-label、id 等能稳定标识元素的属性统称为锚点；把 ReproBreak 标注的新定位器能被 L1 抽取记录覆盖并解析的比例称为静态可解析率。真实目标移除对照实验指：从候选集中移除真实目标元素，再观察修复器是否输出弃权。

这段话一次解决四个问题：定位器/选择器的分工、锚点的定义、可达率的改名、以及“解析”到底指什么。
