Research on silent false healing in Playwright test repair

**摘要：**针对Playwright自动化测试中定位器易失效问题，本文研究大语言模型驱动测试自愈过程中的隐性误修复风险。本文以ReproBreak数据集中koenig项目的真实失效用例为研究对象，构建HealReact静态基线，并在选择器解析层面对修复行为进行量化分析。结果表明，当目标元素缺失时，朴素修复器易生成可解析但指向错误元素的选择器；相比之下，静态基线可覆盖多数真实失效目标。据此，本文建议在持续集成场景中引入行为重放验证机制，以有效降低误修复风险。

**关键词：**测试自愈；大语言模型；Playwright；React；隐性误修复

**Abstract:** This paper investigates the risk of silent false healing
in large language model (LLM)-driven self-healing for Playwright tests
with brittle locators. Using real break cases from the koenig project in
the ReproBreak dataset, the study builds HealReact, an abstract syntax
tree-based static substrate, and analyzes repair behavior at the
selector-resolution level. The results show that, when the target
element is missing, a naive repairer easily generates resolver-valid
selectors for wrong elements, while the static substrate covers most
real break targets. The study indicates that continuous integration
scenarios require a behavioral replay verification mechanism to reduce
false-healing risk.

**Key words:** self-healing test; large language model; Playwright;
React; silent false healing

**0 引言**

用户界面（User
Interface，UI）测试套件的维护是现代Web工程中的持续性成本来源。一次层叠样式表（Cascading
Style
Sheets，CSS）类名重命名、一次React组件重新嵌套，或一次行为不变的处理函数重构，都足以使数十个端到端（End-to-End，E2E）Playwright测试失效。这一问题在图形用户界面（Graphical
User
Interface，GUI）测试录制重放与自动生成研究综述中被多次列为关键挑战^\[1-2\]^。国内行业期刊也持续关注软件测试自动化方法及测试技术工程化实践，相关研究为工程化测试维护问题提供了应用背景^\[3-4\]^。无论是工业界工具（如Healenium）还是持续增长的学术工作^\[5-6\]^，相关方案通常都将测试自愈机制作为应对路径，即在定位器失效时由修复器自动将其重写为指向新文档对象模型（Document
Object Model，DOM）中等价元素的形式。近年来，大语言模型（Large Language
Model，LLM）被广泛引入软件测试与修复任务^\[7-8\]^，自动测试修复（含定位器修复）已成为其中最直接且核心的应用方向。

尽管该研究方向前景广阔，但现有文献普遍高估了问题的解决程度。Joseph^\[5\]^基于特定可访问性结构在单一用例上实现了100%通过率；现有基于LLM的定位器修复研究亦多通过一致性安全约束来彰显其高成功率。然而，这些指标存在共同的结构性盲区：其仅关注测试脚本的"表面通过"，而非修复后选择器与开发者预期语义的"真实对齐"。由于修复器通常具备强行生成可解析选择器的倾向，这种盲区极具隐蔽性，导致每一次"通过但错指"的隐性误修复都会掩盖本应暴露系统缺陷的真实UI变更。

本文在ReproBreak^\[6\]^数据集的真实Playwright失效用例上，对该隐性误修复模式进行了直接量化测量。针对koenig项目的75个可达失效用例，主要实验发现如下：

发现1：隐性误修复是模型的默认行为，且软提示中的放弃约束失效。当真实目标元素被强制从候选集中移除时，朴素LLM修复器（Qwen2.5-Coder-7B^\[9\]^）在78.7%的用例中（59/75）给出了语法正确但指向错误元素的选择器；仅在17.3%的情景下能正确触发放弃机制。即使在系统提示（System
Prompt）中追加明确的"如无契合候选则放弃"约束，其评估结果亦完全一致（两组实验均为59/75，$\Delta = 0$），表明模型未能将该规则有效纳入推理决策。

发现2：采用低开销的确定性方法可在实现局部改进的同时保持零回归。HealReact的L1静态基线在koenig项目上对真实失效目标的覆盖率可达80.6%（75/93）；在可达用例中，L3修复器首位候选选择器（Top-1）的精确匹配率为77.3%（58/75）。进一步通过双因子析因分析分离变量发现，data-testid加权检索与强锚点后置过滤均带来了边际改进，合计新增3个正确修复用例且表现出零回归（尽管优化方向一致，但在$n = 75$的样本量下McNemar检验结果未达统计学显著水平）。

发现3：跨应用泛化能力受到代码库锚点约定差异的严重制约。在另一React+Playwright代码库（payloadcms/payload，含319个失效配对）上，由于其广泛采用块、元素、修饰符（Block
Element
Modifier，BEM）风格的模板字面量类名，导致当前的静态抽取器无法对其进行有效求值，原始可达率从koenig的80.6%急剧降至3.8%。研究将其诊断为一种明确且可修复的工程盲区，而非对方法论本身的否定。

综上所述，前两项发现为在无人值守的自愈流水线中引入行为重放验证机制提供了直接的实证动因。而第三项发现则提出了一个具有可证伪性的跨应用泛化命题：任何仅在单一应用上进行基准测试（Benchmarking）的定位器修复工具，都极易高估其泛化能力，因为锚点约定（如data-testid、data-kg-\*与BEM模板字面量）在不同的React代码库之间存在显著的异构性。

此外，本文构建了HealReact的L1静态基线。该基线由基于抽象语法树（Abstract
Syntax
Tree，AST）的抽取器与具备确定性后置校准的LLM派生意图标注器共同组成，在静态层面实现了对koenig项目93个失效目标中80.6%的覆盖。在此基线之上，轻量化本地L3修复器在可达用例上的选择器精确匹配率达到77.3%，在全数据集上的静态修复代理指标为62.4%。

需要说明的是，本文统一采用"静态修复代理指标"而非运行时"端到端修复率"。该指标侧重于选择器解析层面的替代性评估。虽然解析器在元素层面的精确一致性与Playwright的运行时通过率高度相关，但二者并不存在严格的上下界包含关系：静态精确匹配的选择器可能因运行时可见性或时序约束（Timing
Constraints）而失效；反之，静态不匹配的选择器亦可能在动态重渲染的DOM中意外通过。因此，两者的准确映射仍需依赖基于Docker的真实行为重放验证。

进一步的变量分析表明，经双因子析因分析解耦后，data-testid加权检索与强锚点后置过滤这两个低开销的确定性机制均带来了边际性能提升，合计新增3个正确修复用例且未引入任何回归缺陷。这一实验结果表明，相比于单纯的提示词工程（Prompt
Engineering），确定性的后处理机制能够为自动化测试自愈提供更具鲁棒性的兜底保障。

本文主要贡献：

1.  在真实Playwright数据集上对隐性误修复进行诊断性测量，证实了软提示放弃指令的失效性；

2.  构建了可本地运行且具可证伪性的HealReact L1静态基线；

3.  通过双因子析因分析解耦了两个确定性安全策略的边际改进，实现了零回归性能优化（优化方向一致，但在$n = 75$下McNemar检验未达显著）。

实验测得的78.7%构成了选择器层面的对抗性上界。若将该值与实际不可达的18/93用例进行乘积外推，可得出无人值守工作负载下隐性误修复率的粗略上界估计约为15%（而非实测部署率）。

评估结果表明，该风险已显著超出工程安全阈值。因此，不宜在持续集成（Continuous
Integration，CI）流水线中引入无人值守机制，来直接自动提交由大语言模型（LLM）生成的选择器补丁。

**1 背景与相关工作**

**1.1 定位器脆性与基准数据集**

ReproBreak^\[6\]^是迄今规模最大的可复现定位器失效数据集，包含来自359个包含Cypress/Playwright测试的Web仓库中的449个可复现失效。本文以tryghost/koenig^\[10\]^的Playwright测试切片作为主要评估对象，该切片包含分布于19个代码提交中的93个可复现失效。

**1.2 自愈工具**

测试自愈可视为测试失败后的自动修复问题，即系统需在既有测试语义约束下生成候选补丁，并避免接受"表面通过但实质错误"的补丁。自动程序修复（APR）的相关文献为该框架提供了研究背景^\[11\]^。工业界常用的Healenium在运行时通过DOM相似度修复Selenium选择器。Joseph^\[5\]^基于DOM可访问性树确定性地重新抽取选择器，在单一电子商务演示样例上实现了100%通过率，是确定性静态修复的代表性基线，也是与HealReact
L1静态基线最直接的对比对象。据目前文献检索，尚未见同行评议的LLM定位器修复工具在真实Playwright基准数据集上分析隐性误修复率；近期的相关工作主要关注修复成功率或解释一致性，二者均未直接应对本研究探针所针对的失败模式。

**1.3 缺失的部分**

上述工作均未在真实基准数据集上隔离并量化隐性误修复率，即修复器给出语法正确但指向错误元素的选择器，从而掩盖真实UI变更的比例。Joseph仅在目标元素按构造必然可达的演示样例上评估了通过率；ReproBreak提供了数据集，但未在其上评估具体的修复器。本研究通过引入对抗性构造的探针填补了这一实证空缺。

**1.4 React相关细节**

koenig-lexical^\[10,12\]^是一个基于React与Lexical的现代富文本编辑器，其Playwright测试套件高度依赖自定义data-kg-\*属性（约占失效总数的一半）而非标准data-testid。payloadcms/payload^\[13\]^则是一个Next.js后台UI，其CSS类名遵循BEM规范^\[14\]^并使用\${baseClass}\_\_suffix模板字面量。此类动态字面量对React运行时可见，但对纯文本AST抽取器隐蔽。本研究对这两种锚点约定的对比分析，构成了后续揭示跨应用泛化瓶颈的实证依据。

**2 HealReact L1静态基线**

HealReact被设计为按"静态→行为验证"递进的四层流水线。其中，L1（静态AST锚点基线）负责从源码静态抽取候选元素；L2（运行时DOM捕获层）负责补足仅在运行时渲染且静态不可见的元素；L3（LLM选择器修复器）负责在前两层产出的候选上推断修复后的选择器；L4（行为重放验证器）负责以真实重放证伪"通过但错指"的补丁。L1--L4属于本研究提出的自定义分层架构。本工作重点实现并评估了L1与L3核心层，L2与L4目前仅作为架构设计占位。

HealReact的L1层是L3修复器与后续行为验证器（L4）所依托的静态基线，其由三部分组成，如图1所示。

**2.1 AST抽取器**

基于ts-morph^\[15\]^构建的抽取器遍历目标目录下所有.tsx/.jsx文件，为每个交互式JSX元素生成一条JSON格式的LocatorSheet记录。每条记录包含元素tag、父链、role、data-testid、aria-label、id、className及自由文本，自定义data-\*属性则捕获于dataAttrs映射中。该抽取器将所有承载稳定锚点（如data-testid、data-cy、data-kg-\*、aria-label或驼峰式testId属性）的JSX元素均视为交互对象，而不局限于标准HTML标签集。这一改进将koenig-lexical上的锚点覆盖率从22%提升至48%，解析器命中率从0%提升至71%，揭示了现代React自动化测试的部分脆弱根源来自自定义包装组件。

**2.2 意图标注器与校准器**

HealReact引入了LLM意图标注流程，通过Ollama^\[16\]^运行Qwen2.5-3B，并结合组件源码与JSX上下文为交互元素生成功能性意图标签（如submit-order-button）。随后，由十条规则（A--J）构成的确定性校准层负责识别并降低可疑标签的置信度，可疑模式包括兄弟集合标签塌缩、标签名词退化及role与intent不匹配等。针对被标记记录，系统重新提交至Qwen2.5-Coder-7B重新标注，形成"低开销至高开销"的分级验证机制。范围说明：意图层的评估目前限定于32个元素的构造样例集；后续针对真实失效用例的定量评估仅依赖抽取器输出的锚点与词法检索，未启用L1意图标签。在大规模真实代码库上的意图稳定性评估仍超出本研究范围。

**2.3 定位器解析器作为可证伪的透镜**

本研究构建了Playwright选择器解析与匹配器，可接收任意选择器表达式（如page.locator、getByTestId、原始CSS等），并返回其潜在匹配的LocatorSheet记录集。该解析器是后续实验论断的核心判定工具：可达性定义为"失效选择器能否解析到sheet中的特定记录"，L3正确性则定义为"解析器能否将LLM修复的选择器与真值选择器映射至同一元素"。为此，解析器处理了引号感知的嵌套参数、动态JS表达式属性值及裸属性选择器。因早期版本存在解析缺陷，静态可达率曾被高估至85%--98%，本研究已在严格的效度审计中明确纠正了该问题。

**2.4 核心指标**

针对koenig-lexical的19个失效提交，抽取器在每个提交中平均生成约400条LocatorSheet记录（范围为314--489），静态解析器实现了对真实Playwright失效目标80.6%（75/93）的覆盖。其余18个用例因依赖运行时DOM（如Lexical框架动态渲染的\<p\>节点），属于典型的动态捕获范畴，由HealReact的L2层负责处理。

**3 三个实证发现**

下述结果均源自同一套实验脚本、数据记录与统一判定规则，相关流程具备完全可复现性。整个实验共涵盖两个L3变体和两个误修复探针。

**3.1 复现配置**

为确保实验的可比性，本文固定了如下配置。L3修复器与意图标注器分别通过Ollama部署Qwen2.5-Coder-7B与Qwen2.5-3B模型，且均设定temperature=0。候选检索采用加性词元重叠打分，权重分别设为testId×3、(dataAttr
key/value)×2以及基础属性（aria/id/class/text/path）×1，并截取排序后的前k个候选元素。针对每个失效用例，实验完整记录了其失效选择器、真值选择器、模型候选、解析结果以及是否判定为误修复或精确匹配。代码与数据开源：实验脚本、结果记录及数据快照已公开归档于https://github.com/vgawen/healreact，表1至表5中的统计数据均可通过该归档完全复算。

**3.2 共享L3协议**

在后续的各项评估实验中，L3修复器均通过Ollama以temperature=0调用Qwen2.5-Coder-7B模型。用户提示词由以下三部分构成：(1)原始失效的Playwright选择器；(2)失效行邻近的±3行测试源码；(3)经前述加性词元重叠打分检索出的LocatorSheet前k个候选元素。模型需严格提供三行规范输出：SELECTOR、CANDIDATE_IDX与RATIONALE。本研究未采用JSON格式输出，旨在规避模型因频繁在选择器中生成未转义引号而导致的结构解析异常。对于多重匹配场景，解析器依据(componentFile,
line)顺序提取首次匹配作为目标；此类多匹配选择器虽被特别标记，但定量指标计算仍以首次命中为准。

**3.3 目标缺失下的隐性误修复**

**3.3.1 设置**

针对75个可达的koenig失效用例（即失效版本提交处LocatorSheet中存在真值元素的用例），本研究在相同提示与检索条件下重新运行L3修复器，但将真值元素从LocatorSheet与候选集中强制移除，从而在机制上阻断模型选中正确答案的可能性。此时，正确响应应为触发放弃机制（CANDIDATE_IDX:-1）；任何返回可解析选择器的响应均构成隐性误修复，并静默地将测试脚本重写至错误元素上。

本研究对比了两种提示词变体：

1.  Vanilla：采用与L3基线完全相同的系统提示词。

2.  Abstain：在原有提示基础上显式追加"如无契合候选则放弃"的强约束，向模型强调"隐性将测试重写至错误元素的盲修复其危害远超直接放弃"。

**3.3.3 解读**

本文测得的78.7%构成隐性误修复的上界，归因于每个用例均属于对抗性构造。在混合工作负载下，仅L1静态层中缺失目标的用例面临此风险，本实验中该比例在koenig失效用例中为18/93=19%。经乘积外推可得到约0.19×0.79=15%的粗略风险估计，而非实测部署率，因为对抗性探针的行为未必会完全迁移至运行时真实可达的用例。但即使仅作为风险估计，本研究仍认为该风险已高到不宜允许CI在无人值守条件下自动提交LLM生成的选择器补丁。

\"Vanilla\"与\"Abstain\"间的等同性表现更具诊断价值，且该等同性在逐用例层面完全成立。表2显示，75个用例的配对判定结果无一发生改变。这一结果表明，7B规模的代码模型在当前任务中，不会因提示词层面的软放弃约束而改变其可观察行为。任何鲁棒的放弃机制都必须构建于模型之外，例如确定性的检索分数阈值、锚点类别归属规则，或能动态证伪修复补丁的行为验证器。该实证结果表明，应将HealReact的L4层（行为重放验证器）作为下一阶段的构建重点，而非继续依赖提示词层面的防御机制。

**3.4 L3基线与两个低开销确定性手段**

**3.4.1 设置**

在相同的75个可达koenig失效用例上，本研究评估了两个L3变体：

1.  v0（基线，双策略禁用）：候选元素依据与失效选择器的词元（Token）重叠度进行检索，所有锚点（含testId）统一权重；无后置过滤；仅通过系统提示词要求模型优先选择testId类锚点。

2.  v1（双策略全开）：(1)
    检索打分器将testId匹配加权（×3）排在dataAttr键值对（×2）和基础属性（×1）之上；(2)
    引入确定性强锚点后置过滤器：若所选候选携带可静态求值的testId但模型给出的非testId选择器，则确定性重写为getByTestId(testId)（对不可求值的JSX表达式则不作重写）。系统提示词保持不变。

为分离两项策略的独立贡献，本研究采用双因子析因设计（testId加权∈{关,开}×后置过滤∈{关,开}）全面运行了4个实验组（表4）。所有实验均基于Qwen2.5-Coder-7B模型、设定temperature=0并采用相同系统提示词；基准真值（Ground

**3.5 跨应用泛化与BEM盲区**

**3.5.1 设置**

任何仅在单一应用上完成的实验均可能受限于该系统的特定约定。为此，本研究引入payloadcms/payload^\[13\]^作为第二个React+Playwright代码库进行对照分析。在不修改L1抽取器的前提下运行于其packages/ui/src目录，共产出457条记录，并对319个失效配对执行new_locator字符串解析匹配，借此评估跨应用可达性的动态变化。

该实验结果并非对HealReact

**4 讨论与局限**

**4.1 78.7%对无人值守CI自愈的工程启示**

LLM自愈的常见部署模式通常具备高度自主性：一次端到端测试失败会触发修复补丁的生成，并由CI自动提交或作为拉取请求（PR）评论发出。根据对抗性上界进行粗略外推，在缺乏行为验证器的此类部署中，约15%的真实Playwright失效用例存在被静默改写至错误元素的风险（此数值仅为粗略上界估计，非实测部署率）。该风险的本质危害并不在于"修复失败导致构建阻塞"，因为这本就是测试的固有职责；而在于"修复器使构建伪通过，但实际指向了错误目标"。

**4.2为什么软提示安全防御会失效**

\"Vanilla\"与\"Abstain\"提示策略的等同性表现（表1）具有明确启示。一种可能解释是，系统提示中"必要时放弃"的软约束指令，在模型内部推理时需要与"生成有效输出"这一更强先验进行竞争，导致其在多数情况下处于劣势；该结论属于机理层面的推测，本研究未进一步开展训练动力学验证。但从工具设计角度看，该结果表明防范误修复的安全保障必须构建于模型之外，例如采用确定性的检索分数阈值、锚点归属规则，以及能够动态证伪修复补丁的行为验证机制。

**4.3 为什么低开销确定性机制优于提示工程**

data-testid加权检索与强锚点后置过滤的运行机制较为直观。经双因子析因分析解耦后，这两项策略分别贡献了2个、合计3个精确匹配增量，且均未引入回归缺陷（表4）。尽管优化方向完全一致，但在$n = 75$样本量下经McNemar检验未达统计学显著水平。因此，本研究不盲目宣称其统计显著性与跨场景泛化性，而是将其归结为HealReact的一条局部设计经验：相比于依赖系统提示词（System
Prompt）由模型内化约束，直接在候选池中显式强化锚点优先级并配合输出后置过滤，在工程上表现出更高的可靠性且具备零回归优势。

**4.4 局限**

模型单一性带来的有效性威胁。本文的数据均基于单一开源轻量级代码模型（Qwen2.5-Coder-7B）。前沿大模型（如GPT-4等）能否在隐性误修复维度上显著缩小差距仍需后续实测；但根据\"Vanilla=Abstain\"等同性机理推测，若缺乏外部确定性验证器，单纯扩大模型规模未必能弥合该差距。基准数据集范围。核心实验结果源自单一React+Playwright代码库koenig；尽管评估随后扩展至payload项目，但其可达率仍受到BEM类名解析盲区的制约。静态修复代理指标与运行时通过率。L3修复器的77.3%与62.4%反映的是选择器解析层面的精确一致性。其与真实运行时通过率的映射关系，仍需在ReproBreak提供的逐版本提交环境中通过Docker行为重放来建立。作为可行性验证，本文对3个静态精确匹配用例（编号615、702、703）进行了Docker运行时重放：三者的修复基线均通过；而替换为HealReact生成的选择器后，2个用例运行通过，1个用例因等待getByTestId(\'color-picker-toggle\')超时而失败。此小规模验证虽无法外推全量通过率，但证实了静态匹配结果既有成功迁移至运行时的案例，也可能因可见性、时序或上下文差异而失败。因此，本文坚持将上述数据界定为静态修复代理指标，而非端到端通过率。

**4.5 有效性威胁**

78.7%这一数据严重依赖于解析器语义。具体而言，resolve_locators.py将动态JS表达式属性值视为潜在匹配，并对复合CSS采用祖先过近似策略；这两项设定虽在错误排查场景下具有合理性，但在边界情况下相对宽泛。在对解析器假设进行审计后，本文修正了早期虚高的可达率声明，收紧假设后将80.6%作为基准数据。鉴于该解析器是评估"正确匹配、误修复、可达率"的核心判定依据，其判定边界会直接影响定量指标，为此本文进行了permissive/strict双假设的敏感性扫描（表6）。核心实验结果中的80.6%（75/93）源于permissive假设；若关闭上述两处过近似并改用strict假设，可达率将降至54.8%（51/93）。因此，L1静态可达率的合理区间应为\[54.8%,80.6%\]，其中80.6%对应其上界。此外，在permissive假设下，75个可达用例中有46个存在多重匹配，解析器依据(componentFile,line)顺序取首次命中进行消歧；而未解析用例数则从permissive下的18个增至strict下的42个。目前，针对抽样用例尚未利用真实DOM快照进行交叉校验，此项验证将留待后续完成。

**4.6 未来工作**

本文的诊断结论指明了两个可行的工程优化方向：其一，将静态基线扩展至跨锚点约定（如BEM模板字面量、CSS
Modules等），以提升不同React项目中可达率的稳定性；其二，基于上述实证分析展现的必要性，构建并集成基于网络行为重放的轻量级验证器，作为LLM修复结果的下游安全屏障。

**5 结论**

在缺乏行为验证的部署条件下，LLM驱动的Playwright自愈机制极易陷入"测试伪通过、真实回归缺陷被掩盖"的困境。本研究在对抗性极限下的选择器解析层面测得78.7%的隐性误修复率上界，且提示词层面的放弃指令未能带来实质缓解；作为静态诊断指标，该数值与运行时测试通过率的映射关系仍需基于Docker的真实重放来确定。此外，HealReact的L1基线实现了对koenig数据集中80.6%真实失效目标的静态覆盖；轻量化本地修复器在可达用例上的Top-1选择器精确匹配率达77.3%；两种低开销的确定性机制进一步实现了帕累托优化。上述结果为后续引入行为重放验证提供了直接的实证动因，也提出了一个受锚点约定差异制约的、具可证伪性的跨应用泛化假设。
